## Активная работа

**Этап 4 — Уведомления и напоминания.** Код готов, локально проверен smoke-тестами (Docker), ждёт живой верификации. Сделано: перенос из аналога напоминаний «скоро продление» — три порога early/soon/last (в `bot_settings`, дефолты из `.env`: day/3/1/0), джоб APScheduler `run_reminder_check` каждые `reminder_check_interval_min` мин (дефолт 60), защита от дублей через `subscription_reminders` (atomic claim ON CONFLICT DO NOTHING; за проход шлём только самое срочное, пропущенные окна занимаем без рассылки). Уведомление «подписка закончилась» + закрытие доступа — с этапа 3. По решению заказчика (2026-07-08) сделано **рабочее продление**: `NAV_RENEW` открывает тарифы активным подписчикам; `activate_payment` отсчитывает новый срок от текущей `end_date` (оплаченные дни не теряются), `start_date` = момент оплаты; guard в `run_expiry_check` не кикает продлившего. Затронута платёжка этапа 2 (`activate_payment`, `pay_create`, `start_payment` kind=renewal). Миграция `0007_reminders`: `bot_settings` + `subscription_reminders`. Smoke: early→идемпотентность→last→всё занято; пороги из БД применяются на лету; продление от конца текущей подписки; guard кика.

**Этап 3 — Управление доступом в чат.** Код готов и локально проверен. Перенесены из аналога: `handlers/join.py` (авто-одобрение join-request по активной подписке, decline без неё), `services/subscriptions.py` (кик из группы ban+unban, `run_expiry_check`), `repo.expire_due_subscriptions`, экран «Моя подписка» (`handlers/subscription.py`), клавиатуры/тексты доступа. APScheduler в `main.py` крутит проверку окончаний каждые 30 мин; в allowed_updates появился `chat_join_request`. Smoke (Docker): нет подписки→не активна, активная→видна, истёкшая→`expired` и не активна, повтор проверки идемпотентен. **Живьём (в конце):** нужен бот-админ в закрытом чате `-1003546154644` + инвайт «по заявке» — тогда заявка оплатившего одобряется, по окончании — кик.

## Протокол обновления

**При старте сессии**:
1. Прочитать этот файл.
2. `git tag -l "stage-*"` и сверить с колонкой «Закрывающий тег». Тег без записи в таблице = таблица устарела, обновить.
3. `git log --oneline -10` — что менялось последним.
4. Только после этого приступать к работе.

**При взятии этапа в работу**:
1. Обновить «Текущий этап» и «Активная работа».
2. Статус 🚧 в таблице.
3. Закоммитить отдельно: `chore(status): start stage N`.

**При закрытии этапа**:
1. Убедиться, что все чекбоксы в `07_ROADMAP.md` отмечены `[x]` и реально проверены.
2. Создать тег: `git tag stage-N-done -m "<описание>"`.
3. В таблице: ✅, «Закрывающий тег», «Последний коммит», «Дата закрытия».
4. Добавить запись в «Историю закрытий».
5. Указать новый «Текущий этап» и «Следующий шаг».
6. Закоммитить: `chore(status): close stage N`.

**Если этап заблокирован**:
1. Статус ⏸ в таблице.
2. В «Известные блокеры»: что блокирует, кого ждём, что нужно для разблокировки.

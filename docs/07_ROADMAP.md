# Дорожная карта реализации — maria_doll

Бот платного клуба **@Fit_it_bot** (клиент Maria_Doll / dolbikfit) + веб-админка.
Адаптация клубного среза из проекта-аналога `club_bot` (**код аналога не трогаем**,
берём как готовый источник). Платёжка — **Продамус** вместо ЮKassa.

Ключевая идея: **MVP-first** + **переиспользование готового кода аналога, а не письмо с нуля**.
Всё редактируемое содержимое (тексты экранов, тарифы, промокоды, настройки) хранится в БД
и правится из админки — как в аналоге. Архитектура сразу закладывает будущие реккуренты Продамуса.

> **Где смотреть прогресс**: текущий статус всех этапов — в [`STATUS.md`](STATUS.md).
> Внутри каждого этапа ниже — чекбоксы acceptance-пунктов. Закрытие этапа → git-тег `stage-N-done`.

## Этап 0 — Фундамент

**Цель**: пустой, но рабочий проект — есть всё для следующих этапов; поднимается локально.

**Что делаем**:
- Свой git-репозиторий (папка сейчас лежала внутри чужого репо) → remote `dimatolpygin/maria_doll`.
- Скелет из аналога: `config.py`, `db.py`, `migrate.py`, `logger.py`, `main.py`, `cache.py` — адаптированные (схема `maria_doll`, без билетов/событий/рефералки).
- `docker-compose.dev.yml` (pg/redis уже подняты на ПК — используем их, порты не пробрасываем), `Dockerfile`, `requirements.txt`, `.env.example`.

## Этап 2 — Оплата Продамус (разовая)

**Цель**: пользователь реально оплачивает подписку через Продамус, бот фиксирует оплату.

**Что делаем**:
- Сервис `services/prodamus.py`: генерация ссылки на payform (`dolbikfit.payform.ru`) с подписью (секретный ключ), сумма из тарифа.
- Подтверждение оплаты **вебхуком** (решение заказчицы): Продамус шлёт notification на наш HTTPS-эндпоинт (домен `dolbikfit.ru` есть), проверяем подпись, идемпотентно создаём подписку. Эндпоинт можно поднять в веб-слое (FastAPI) или отдельным лёгким приложением. Архитектуру заложить под будущие реккуренты.
- Запись подписки в БД: старт/окончание, привязка тарифа и зафиксированной цены.

**Критерии приёмки** (закрытие → tag `stage-2-done`):
- [x] Пользователь выбирает тариф → бот отдаёт рабочую ссылку Продамус на нужную сумму.
- [x] После оплаты вебхук Продамуса ловится, подпись проверяется → в БД создаётся подписка с корректными датами.
- [x] Повторный вебхук (та же оплата) не создаёт вторую подписку.
- [x] Бот сообщает пользователю об успешной оплате.

> Проверено вживую 2026-07-07 (демо-оплата Продамуса тестовой картой через туннель):
> вебхук принят, подпись сошлась (после фикса экранирования слэшей), подписка
> создана, уведомление доставлено. Идемпотентность — smoke + повторные уведомления.

- [x] Неоплативший подаёт заявку → бот не одобряет.
- [x] По окончании подписки бот кикает из чата.

## Этап 4 — Уведомления и напоминания

**Цель**: бот сам ведёт коммуникацию по жизненному циклу подписки.

**Что делаем**:
- Перенос `services/reminders.py`: напоминания «скоро продление» (пороги настраиваемы).
- Логика неуспешного списания: 2–3 попытки за 2–3 дня + уведомление, потом закрытие в день окончания (пока разовый платёж — заготовка под реккуренты).
- Уведомление «подписка закончилась».

**Критерии приёмки** (закрытие → tag `stage-4-done`):
- [x] За N дней до конца приходит напоминание о продлении.
- [x] В день окончания приходит уведомление, доступ закрывается.
- [x] Пороги напоминаний настраиваются из БД/настроек.

> Проверено вживую 2026-07-08 на короткой подписке (10 мин, `REMINDER_UNIT=minute`,
> пороги 5/2/0): пришли early → soon → last, затем «подписка закончилась» + кик.
> Продление проверено: кнопка «Продлить» у активного подписчика продлевает доступ
> от текущей даты окончания (дни не теряются), кика нет. Пороги правятся из
> `bot_settings` без рестарта (fallback — `.env`).
